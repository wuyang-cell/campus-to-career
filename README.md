# campus-to-career · 从校园到职场

> 一个给 AI 用的求职决策工具，覆盖大一规划到试用期转正。

**它不是求职课，也不是简历模板库。** 它是一套决策规则：每个节点该做什么决定、做到什么程度可以停、什么时候该退回上一步。

---

## 一、解决什么问题

大多数人求职失败，不是因为能力不够，而是因为顺序错了：

- 先改简历再想方向，改完才发现投的岗位不对
- 先租房再找工作，通勤半径把岗位池锁死了一半
- 先担心转正，最后才对齐 KPI，做满三个月才发现方向不对
- 拿"太卷"当结论，但一次都没投过

这个 skill 只做两件事：**把顺序摆正，给每一步一个可验收的停止条件。**

## 三、三条设计原则

### 1. 顺序优先于能力

**但这条有前提**：能力差距在 1 档以内（学过、做过小的，但没作品）。差 2 档以上（零基础跨大类），先补能力，顺序再对也没用。

### 2. 证据分层

每条结论必须带标签，没有标签的数字不进结论句：

| 标签 | 含义 |
|---|---|
| `[规则]` | 内置判据，不随时间和地域失效 |
| `[检索·yyyy-mm·信源]` | 联网查到的，标日期与来源，6–12 个月失效 |
| `[自填·日期]` | 用户提供的数据 |
| `[推断]` | 推出来的，不是查到的 |

**会过时的是事实值，不会过时的是关系式。** 所以 skill 里没有"房租不超过 1500"这种话，只有"可承受月租 = 税后月薪 − 吃饭 − 通勤 − 净收入底线"。

### 3. 判停优先于优化

每个模块都有停止条件。目的是防止两件事：**无限改简历**、**拿"再想想"拖延**。

## 四、适用范围

**地域：中国大陆。** 政策（青年驿站、社保、劳动合同）、数据源（工信部、国家邮政局）、法规全部是中国大陆口径，换个国家不成立。

**人群**：大一到大四在校生 + 毕业 1 年内。

**不适用**：在职多年跳槽、创业、自由职业、留学申请、考研考公（这个 skill 只服务就业方向）。

## 五、怎么用

### WorkBuddy

把整个目录放到 `~/.workbuddy/skills/campus-to-career/`。

### Claude Code / 其他支持 Agent Skills 的工具

放到对应的 skills 目录。frontmatter 里 `name` 和 `description` 是通用字段；`display_name`、`tags`、`agent_created` 等是 WorkBuddy 专用，其他平台会忽略，不影响使用。

### 只想知道内容

从 `SKILL.md` 读起——它是入口、路由表、红线和贯穿规则。其余文件按需查。

### 脚本依赖

`scripts/` 需要 Python 3.10+ 与 `requests`、`beautifulsoup4`。**不装也能用**——检索模块的方式 3（搜索引擎聚合）零依赖。

### 更新

**已经下载的副本不会自动更新。** Git 是分布式版本控制，GitHub 不会向任何人推送改动。

| 你怎么拿到的 | 怎么更新 |
|---|---|
| `git clone` | `git pull` |
| 下载 ZIP | 重新下载，覆盖旧目录 |
| 从市场安装 | 手动重新安装 |

**当前版本见 `SKILL.md` 的 `version` 字段。** 改了什么、为什么改，见 [CHANGELOG.md](CHANGELOG.md)——里面也记了被推翻的改动。

## 六、边界与局限

**它现在是一个"知道该问什么问题"的工具，不是一个"知道答案"的工具。**

下面五条是**已经处理过的边界**，不是待修的问题。每条都写了它为什么存在、怎么应对——以及哪一条仍然真的是缺口。

| 边界 | 怎么处理的 |
|---|---|
| **不规定"投多少份之后该做什么"** | 什么时候改简历、改几轮、换不换方向，**由使用者自己决定**。skill 只给诊断、修改意见和从零构建的方法。数值（转化率、权重）都标成默认值，不是标准。见 `90-rules.md` 第八节 |
| **数据实时查，不写死** | skill 里只留两类：关系式（公式、判据）、标了年份的年度数据。租金、薪资、在招岗位、驿站政策**一律当次检索**——写死了就要维护，维护就会滞后。见 `91-data-sources.md` 7.1 |
| **代理指标给参考，不做穷举验证** | 软件、电商有两个已核案例；其余给「三步推导法 + 参考表」，由使用者按自己的岗位套。已修正一条原则：**优先找「岗位存量」，其次才是「雇主产出」**（护士数优于床位数，教师数优于学生数） |
| **M1 / M2 只做了桌面推演** | 大一路径已修正：无方向时按「跨行业可迁移性」选技能，默认数据分析/Excel。但仍缺真实样本 |
| **不承诺结果** | 不写"按这个做就能拿到 offer"。结果不可控，工具只负责把可控的部分做对 |

### 一条自我限制

这个 skill 里所有数字都能被追问三句：**谁给的、什么年份、换个对象还成立吗。**

答不出来的，标 `[推断]` 或删掉。这条对自己写的内容同样适用——见 `94-maintenance.md` 第 1.4 条。

## 九、想改它

先读 `references/94-maintenance.md`。里面写了改动前的三条硬规则、冲突裁决的优先级、和一条最容易被忽略的要求：

> **凡写具体结论，先问它换个岗位、换个行业、换个城市还成立吗。**
> 只对某次测试成立的结论，不是规则，是案例。
