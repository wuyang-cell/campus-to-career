# 数据源与检索口径

> 这份文件只回答一件事：**每个数字从哪来、怎么查、怎么标、什么时候作废。**
> 原则：宁可说"查不到"，不用常识填补。

---

## 一、信源分级

| 级 | 类型 | 可用于 | 举例 |
|---|---|---|---|
| **A** | 官方 / 统计口径 | 可作结论依据 | 统计局公报、人社局、团委、公安户政、公积金中心、教育局/学校就业网 |
| **B** | 商业平台原始数据 | 可作区间参考，须标口径 | 贝壳/链家/自如、BOSS直聘/猎聘、薪酬报告 |
| **C** | 社区与个人发布 | **只作交叉验证** | 豆瓣小组、小红书、闲鱼、贴吧、知乎回答 |
| **D** | 引流内容 | **禁用** | "XX 市租房避坑必看""内行人告诉你"类营销号、无署名榜单 |

**判定**：说不出"数据怎么来的、口径是什么、什么时候采的"，降到 C 或 D。

### 1.1 内容类信源：怎么判断能不能用

数据类信源看口径，**内容类信源看"有没有具体场景"**。

| 形态 | 用来做什么 | 怎么判断质量 |
|---|---|---|
| **短视频** | **发现问题**，不提炼结论 | 看评论区：在**分享自己经历** = 真内容；在刷"学到了""收藏了" = 流量话术 |
| **长文**（公众号/知乎/手册） | **解决问题**，提取条件分支 | 有没有反例与条件限定。只给结论不给条件的，降级 |
| **论坛面经** | 补具体场景 | 只取近一年、写明公司与轮次的 |

**短视频不要用来提炼结论**——它的结论都是清单体（"3 个技巧""5 个坑"），正确但无用。它的价值在于**暴露真实问题**：评论区反复出现的困惑，才是该补的场景。

**长文的价值在于条件分支**：好的长文会说"如果 A 就 X，如果 B 就 Y"，这正是短视频给不了的。

**一句话**：短视频找"用户在问什么"，长文找"这个问题怎么答"。

## 二、九维城市数据

### 2.1 岗位数量

```
1. 平台搜「城市 + 岗位名」（用 JD 里的词，不用行业词）
2. 取前 30 条
3. 记录公司名 + 行政区
4. 统计行政区频次，前 2 名 = 求职半径
5. 记录"常年挂招"的公司（同一公司反复出现）
```

**注意**：平台个性化推荐会污染结果。无痕模式、清空筛选、换关键词再查一次。

**输出**：`[检索·2026-11·BOSS直聘] 广州·运营助理，前 30 条中天河 11、番禺 6、海珠 5`

**抓不到平台数据时，改用产业代理指标**（详见 `05-city.md` 2.2.1）：

| 序 | 指标 | 信源级别 | 说明 |
|---|---|---|---|
| 1 | 软件业务收入（分城市） | A | 工信部《软件业运行情况》；城市口径由各市工信局公布。**软件/IT 岗首选** |
| 2 | 涉软企业数 / 规上企业数 | A | 市工信局、软件行业协会 |
| 3 | 软件从业人员数 | A | 市统计年鉴「信息传输、软件和信息技术服务业」 |
| 4 | 数字经济核心产业增加值 | A | 市统计局。含硬件，会高估软件岗 |

**用法**：只用于城市间排序，不用于给绝对岗位数。输出必须标「估算，未核」。
**禁止**：把营收直接说成"岗位多"。

**已知的坏数据源**：豆丁网、道客巴巴、各类"XX 强城市报告"转载稿。这类文档常出现**多个城市数值完全相同**（如北京/上海/深圳/成都软件业务收入并列为同一数字），或与工信部口径差一个数量级。见到"数据来源：第三方资料、业内专家采访整理"要直接降为 D 级。**2026-11 实测遇到过一次，同一张表里四个城市数值一模一样，与官方公布相差 8 倍。**

### 2.2 岗位适配度

```
对比你的学历/经验与该城岗位要求：
- 学历要求分布
- 经验要求（应届/1 年/3 年）
- 是否要求执业资格
```

### 2.3 消费水平

```
租金：贝壳/链家/自如，按片区 + 合租/整租筛，取中位数（不取最低价）
吃饭：外卖/食堂均价
通勤：地铁/公交月卡
```

### 2.4 人口结构

```
信源：当地《国民经济和社会发展统计公报》→ 常住人口增量
不看：网文榜单、自媒体排名
```

### 2.5 GDP 增速

```
信源：当地统计局年度公报
记录：增速 + 与全国平均的差值
```

### 2.6 人才政策

```
只查 A 级：人社局、团委、公安局户政、公积金中心官网
必须记录：发布日期 + 适用条件（学历/毕业年限/社保）+ 申领窗口
```

**先查全国统一入口，不要逐城检索**：

```
青年驿站：https://www.ncss.cn/qnyz/
（国家大学生就业服务平台，教育部与团中央共建；2026-11 核对时已覆盖 200+ 城、2600+ 家）
```

人才补贴**没有**全国统一入口，只能逐城查当地人社局官网或公众号。

**一条贯穿所有城市的硬约束**：驿站要**笔试/面试/入职通知**才批，且通知上要有申请人本人名字。这是普遍做法，不是个别城市。所以驿站**只对"已经有面试的人"有效**，不能算进"先过去再找"的预算。

**必须查的四项（M5 就要查，不留到 M8）**：

| 项 | 为什么 |
|---|---|
| 青年驿站 / 人才驿站：有无、免费天数、学历门槛、申请入口 | 决定"能不能先过去再找"，直接影响第一笔现金压力 |
| 人才补贴：金额、条件、申领窗口 | 多为一次性，且附带社保/落户条件 |
| 落户门槛 | 决定能不能长期留下 |
| 政策时效 | 部分项目是阶段性活动，有明确起止日期，过期即失效 |

**输出**：`[检索·2026-11·成都团市委] 青年人才驿站：全日制大专及以上（含在读）、单次最长 7 天、年累计可到 30 天、23 个区县全覆盖、需面试或入职通知且通知上有本人名字`

**时效提醒**：驿站政策每年调整，动身前一周必须复核一次。引用一律带年份，不写"目前""现在"。

**识别"看着还在、实际已停"**：

| 信号 | 说明 |
|---|---|
| 统一入口点进去 404 / 跳旧链接 | 大概率已停止 |
| 当地公众号最近一篇推文 > 6 个月未更新 | 可能已停 |
| **直接打驿站电话确认** | 最可靠，比线上申请靠谱 |

### 2.7 城市发展规划

```
信源：国土空间总体规划、产业规划、政府工作报告
看：目标产业是否被列为重点发展 / 限制 / 收缩
```

## 三、房源

### 3.1 我能做的

| 能做 | 输出 |
|---|---|
| 按城市给预算上限 | 可承受月租 + 首次入住现金 |
| 按岗位地址给片区 | 1–2 个推荐行政区 + 通勤时间 |
| 给筛选条件 | 合租/整租、民水民电、非隔断、预算区间 |
| 评估用户发来的链接/截图 | 六维评估 + 红旗提示 |

### 3.2 我不能做的

| 不能做 | 原因 |
|---|---|
| 实时抓取贝壳/58/小红书完整房源列表 | 强反爬、分钟级变动 |
| 保证房源真实存在 | 引流房源普遍 |
| 代替看房与签约 | 现场信息无法替代 |

### 3.3 评估用户提供的房源

| 维度 | 看什么 | 红旗 |
|---|---|---|
| 通勤 | 到公司实测时间与换乘 | 地图 40 分钟但换乘 3 次 |
| 价格 | 与同片区均价对比 | 低 30% 以上 = 引流 |
| 水电 | 民用/商用 | 商用未提前说 |
| 硬件 | 空调、洗衣机、热水器、漏水、隔音 | 只有美图无实拍 |
| 合同 | 押付、退租、维修 | 只口头承诺 |
| 安全 | 楼层、门禁、周边 | 一楼偏僻、无门禁 |

## 四、薪资

```
1. 招聘平台同城市 + 同岗位 + 应届/1 年筛选
2. 取区间中位数，记录是"底薪"还是"综合"
3. 交叉：应届生薪酬报告（若有）
```

**必须区分**：无责底薪 / 含绩效 / 含补贴 / 含年终折算。四个口径能差 30% 以上。

## 五、交叉验证

| 数据类型 | 最少来源 | 规则 |
|---|---|---|
| 租金 | 2 | 平台 + 社区，量级一致才采用 |
| 薪资 | 2 | 平台 + 报告，或两个平台 |
| 政策 | 1（必须 A 级） | 只认官方，且看发布日期 |
| 岗位数量 | 1 | 换关键词重复一次，防个性化推荐 |
| 产业分布 | 2 | 政府规划 + 平台实际岗位分布 |

**不一致时**：取区间，不取平均；写明"两个来源不一致，区间为 X–Y"。

## 七、更新与失效

| 数据 | 有效期 | 到期处理 |
|---|---|---|
| 租金 | 3 个月 | 重查，或标 `[过期·需复核]` |
| 薪资带宽 | 6 个月 | 同上 |
| 岗位密度 | 6 个月 | 同上 |
| 产业规划 | 2–3 年 | 看是否有新政 |
| 政策（驿站/落户/补贴） | 以官方公告为准 | 每次使用前重查 |
| 民水民电单价 | 以最近一期账单为准 | 每次签约前核实 |

**用户回填真实数据时**：以用户数据为准，覆盖检索值，标 `[自填·日期]`，注明"已覆盖检索值"。

### 7.1 一条原则：数据一律实时查

skill 里只留两类东西：

| 留 | 例子 |
|---|---|
| **关系式**（不随时间和地点变） | 可承受月租 = 到手 − 固定支出 − 底线 |
| **标了年份的年度数据** | 2025 年南京软件业务收入 1.02 万亿 |

**其余一律当次检索**：租金、薪资、青旅价、在招岗位、驿站政策、房源。

**为什么不写死**：写死了就要维护，维护就会滞后，滞后就误导。**实时查一次的成本，比维护一张终将过期的表低。**

### 7.2 更新手册：每类数据从哪更新

**分两类责任：维护者负责年度数据，使用者负责当次数据。**

| 要查什么 | 去哪查 |
|---|---|
| 软件业务收入（分城市） | 工信部《软件业运行情况》+ 各市工信局 |
| 快递业务量（分城市） | 国家邮政局 |
| 城市分梯队 | 中国软协《软件产业高质量发展报告》 |
| 青年驿站 | `ncss.cn/qnyz/` + 当地团委 |
| 人才补贴 | 当地人社局 |
| 租金 | 贝壳 / 自如 / 安居客 |
| 青旅床位价 | 同程 / 美团 |
| 在招岗位 | 见 `92-job-search.md` |

**维护者的判断标准**：一类数据如果半年内会变，就不该写进 skill。

### 7.3 使用前的时效自检（三句）

看到 skill 里任何一个数字，先问：

```
① 它带年份吗？没有年份 = 不可用
② 年份到现在多久？超过标注有效期 = 重查
③ 它是"事实值"还是"关系式"？
   - 事实值（某城租金 1500）→ 必须重查
   - 关系式（可承受月租 = 到手 − 固定支出 − 底线）→ 永远有效
```

## 八、禁止做法

1. **不用常识填补空白。** 不知道就说"查不到，需要你提供或换个判断方式"。
2. **不把 C 级来源当结论。** 小红书上的"XX 市应届生薪资"只能验证量级。
3. **不给具体房源推荐。** 只给片区、预算上限、筛选条件。
4. **不预测涨跌。** 不判断"这个片区明年会不会涨"。
5. **不引用无日期的数据。** 任何数字必须带采集时间。
6. **不用单一来源支撑重大决策。** 换城市、签约这类不可逆动作，至少两个独立来源。
