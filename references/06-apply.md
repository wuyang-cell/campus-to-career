# M6 · 投递计划

> 解决什么：投多少、怎么分批、什么时候必须停。
> 核心原则：**投递不是撒网，是测量。** 每一批都要能读出断点在哪。

---

## 前置：投递前必须已确定的两个东西

**投递是执行动作，不是探索动作。** 在执行之前，必须已经有两个答案，否则投出去的每一份都无法解读——收到面试不知道为什么成，没有回复不知道为什么败。

| 必须已定 | 判断标准 | 没定怎么办 |
|---|---|---|
| **目标岗位** | 能说出一个具体岗位名，且搜得出 10 条以上真实 JD | 回 M3。**不要用"边投边找方向"代替定方向**，海投找方向等于用随机数据猜因果 |
| **目标城市** | 有 1–3 个候选城市，且已比较过岗位池与生活成本 | 回 M5。城市未定时，通勤半径、岗位池大小、起薪水平都是未知，投递记录无法归因 |

**发现任一未定，先停，回对应模块。** 只做一件事：把缺的那个补上，补完再回来。

**这张表是"没定就回去补"，不是"定了再问一遍要不要放宽"。** 用户已说出岗位和城市，那一问（"就这一个还是别的也行"）在入口问完就关上——他说不考虑，到这里就不再提换城市、换岗位。真需要开口的只有一种情况：检索下来这座城里这个岗位的在招公司够不着 10 家。那时给的是数据，不是意愿——"要么放宽岗位到 __，要么放宽城市到 __，你定"。

**唯一例外**：目标公司是全国远程岗、或已明确"全国可投、城市后定"。此时城市可以在投递后收敛，但**必须先写下"我在什么条件下选哪个城市"的判断规则**，否则 offer 到手仍然要重来一遍。

## 〇、信息源：岗位从哪来，公司怎么查

**这一节比投递技巧更重要。** 投 100 份错的公司，不如投 10 份对的。

### 0.1 岗位从哪来（按转化率排序）

| 序 | 渠道 | 说明 |
|---|---|---|
| 1 | **内推** | 学长学姐、实习同事、行业社群。转化率最高，且能问到真实情况 |
| 2 | **目标公司校招官网** | "加入我们"页面，别等第三方转载。信息最准，流程最正式 |
| 3 | **实习转正** | 大三实习留用是最稳的校招通道 |
| 4 | **学校就业网 / 双选会** | 被低估。对口企业多，竞争小于公开平台 |
| 5 | **招聘平台（BOSS/实习僧/牛客）** | 海投用，**别当主力** |

**结论**：内推 > 实习转正 > 校招官网 > 学校双选会 > 海投。海投是兜底，不是策略。

**怎么把岗位找出来**：用 `references/92-job-search.md` 的内置检索（不需要另装 skill）。它会给出多平台去重后的清单，每条带完整 JD。**但渠道优先级不变**——检索到的是挂牌岗，内推与校招官网仍优于海投。

### 0.2 公司底细怎么查（四步）

| # | 查什么 | 在哪查 | 看什么 |
|---|---|---|---|
| 1 | 工商与规模 | 天眼查 / 企查查 | **参保人数**（< 50 人慎入）、成立时间（< 1 年的初创风险高）、法律诉讼条数 |
| 2 | 真实评价 | 看准网 / 脉脉 | 搜"公司名 + 离职"，看反复出现的问题 |
| 3 | 应届生踩雷 | 小红书 / 抖音 | 搜"公司名 + 避雷"，应届生会发具体经历 |
| 4 | 行政处罚 | 国家企业信用信息公示系统 | 有没有处罚记录、经营异常 |

**为什么看参保人数**：它比"员工规模"真实。一个号称 200 人的公司，参保 30 人，说明大量用外包或没缴社保。

**注意**：评价类信息（第 2、3 步）只作参考，不作为否决依据。离职者评价天然偏负面，要看**重复出现的问题**，不看单条情绪。

## 一、先分流：两种策略

| 你的状态 | 策略 | 判断依据 |
|---|---|---|
| 有明确岗位 + 明确城市 | **定向投递** | 目标清晰，追求匹配度，不追量 |
| 岗位明确、城市无所谓 | **全国分批** | 用城市换机会密度 |
| 都没有 | 回 M3，不要先投 | 方向未定，投了也是浪费 |

---

## 二、定向投递

```
1. 列出目标城市的 20–30 家目标公司（按规模/业务分层）
2. 每家公司查 1–2 个在招岗位
3. 按"冲刺 / 匹配 / 保底"分层，冲刺 ≤ 1/3
4. 每家单独改简历关键词（不改结构）
5. 一周内投完，记录回复
```

**定向投递不追求数量**，追求"每一份都能说出为什么投它"。说不清就不投。

---

## 三、全国分批

**不要同一天铺开所有城市**，按批次推进，每批 1–2 周。

| 批次 | 城市 | 目的 |
|---|---|---|
| 第 1 批 | 首选城市（1–2 个） | 测简历与话术 |
| 第 2 批 | 次选城市（2–3 个） | 扩大机会 |
| 第 3 批 | 保底城市 / 家乡 | 兜底 |

**每批结束看三个数**：投递数、沟通数、面试邀请数。断点在哪，下一批就改哪里。

---

## 四、3 天 × 50 份规则

**这是用户的既定规则**，执行前提必须先确认：

| 前提 | 不满足怎么办 |
|---|---|
| 简历已改满 2 轮、定稿 | 先改完再投 |
| 可投岗位池 ≥ 150 个 | 改为"投满可投岗位"，不硬凑 |
| 岗位与简历方向一致 | 方向不一致，投了也是浪费 |

### 执行

```
Day 1：50 份（保底 + 匹配）
Day 2：50 份（匹配为主）
Day 3：50 份（匹配 + 冲刺）
Day 4：统计，不投
```

### 第 4 天：按转化率分层看，不看总数

**绝对数没有意义。** 投 20 份大厂校招 0 回复是正常的（报录比可到 100:1）；投 20 份中小公司 0 回复才是简历有硬伤。同一个"0"，含义完全不同。

**正确做法：算每一层的转化率，看哪一层断得最厉害。**

| 层 | 怎么算 | 参考区间 | 低于下限 = 这一层有问题 | 改什么 |
|---|---|---|---|---|
| 投递 → 被查看 | 查看数 ÷ 投递数 | 30–50% | **简历入口** | 头像、期望岗位太宽、期望薪资越级、到岗时间写"随时"却没准备好 |
| 被查看 → 沟通 | 沟通数 ÷ 查看数 | 20–30% | **简历内容** | 关键词没对齐 JD、成果无量化、经历与岗位不匹配 |
| 沟通 → 面试邀约 | 邀约数 ÷ 沟通数 | 20–30% | **岗位定位** | 投的方向不对、公司层次错配、城市不匹配 |
| 面试 → offer | offer 数 ÷ 面试数 | 15–25% | **面试表现** | 进 M7，不要再改简历 |

`[通用·2026·平台口径，未复核]` 参考区间来自招聘平台的公开统计，会随岗位类型与城市浮动。**只用于判断量级，不用于精确对标。**

**综合量级**：投 20 份约得到 1–2 次面试；投 150–200 份约得到 1 个 offer。这是量级参考，不是承诺。

**规则**：3 天 150 份后，先算四层转化率，再决定改哪一层。**只有"四层都低于下限"才指向方向问题**——这时继续按原方向投，代价是继续烧样本；某一层低，就只改那一层，不要全盘推翻。

**注意**：如果"被查看"这一层就崩了，问题比简历措辞更靠前——先查地域表述、期望薪资、岗位硬门槛，不要只改措辞。

```
投递数 → 被查看数 → 沟通数 → 面试数 → offer 数
```

| 批次 | 投递 | 查看 | 沟通 | 面试 | offer | 查看率 | 沟通率 | 邀约率 | 断点在哪层 |
|---|---|---|---|---|---|---|---|---|---|
| 第 1 批 | | | | | | | | | |
| 第 2 批 | | | | | | | | | |

**两条原则**：

1. **主要与自己的上一批比**，看改进有没有效果。
2. **参考区间只用来看量级**，不用来精确对标——行业、城市、渠道差异太大。低于下限时，先怀疑这一层，不要直接否定整个方向。

## 六、渠道

| 渠道 | 适合 | 注意 |
|---|---|---|
| 企业官网/公众号 | 目标明确的大公司 | 流程慢，但最正式 |
| 招聘平台（BOSS/猎聘等） | 中小公司、快速沟通 | 注意"常年挂招"的假岗位 |
| 内推 | 有学长学姐/前同事 | 回复率最高，优先用 |
| 学校就业网/双选会 | 校招、本地企业 | 竞争小，岗位质量参差 |
| 社群/小红书/牛客 | 实习、行业信息 | 信息真伪需核 |

**优先顺序**：内推 > 官网 > 平台 > 社群。

---

## 七、招呼话术（3 行以内）

```
我是谁（学校+专业+毕业时间）
+ 我能做什么（1 个与岗位直接相关的成果）
+ 为什么是这个岗位（一句具体的话）
```

**反例**："您好，我对贵公司非常感兴趣，希望能有机会加入贵团队，谢谢！"——没有信息量。

**正例**："您好，我是 XX 大学会计学 2027 届毕业生，做过一份 8000+ 条订单的数据分析，输出过转化率归因报告。看到贵司招数据运营助理，想投递简历。"

## 八、拿到邀约后必问四件事

| # | 问什么 | 为什么 |
|---|---|---|
| 1 | 薪资结构：底薪多少？是否无责？绩效怎么算？ | "综合 8K"可能是底薪 3K + 绩效 5K |
| 2 | 上班时间：双休还是单休？加班有加班费吗？ | 影响实际时薪 |
| 3 | 试用期：几个月？转正标准？工资是否 80%？ | 影响前几个月现金流 |
| 4 | 通勤：公司在哪个区？有班车吗？ | 影响 M8 租房决策 |

**这一轮是采集信息，不是谈薪。** 不要在这时讨价还价。

## 九、Offer 对比（投递的终点）

### 9.1 信息采集

| 项 | 要问到的粒度 |
|---|---|
| 薪资 | 无责底薪 / 绩效基数 / 发放周期 / 补贴 / 年终（几个月，是否保底） |
| 工时 | 双休或单休 / 上下班时间 / 加班频率 / 加班费或调休 |
| 试用期 | 时长 / 工资比例 / 转正标准 / 是否缴社保 |
| 社保公积金 | 缴纳基数（最低还是实际）/ 比例 / 起缴月份 `[待核]` |
| 合同 | 签几年 / 试用期是否写入 / 有无服务期与违约金 |

**口径提醒**："综合 8K" ≠ 月薪 8K；"13 薪"可能按比例折算；"包吃住"要折现。

### 9.2 加权对比

用 `assets/offer-matrix.md`。权重依据价值排序：

```
岗位业务核心度 > 直属领导 > 薪资结构 > 公司平台 > 成长速度 > 工时通勤 > 城市
```

**否决项（不看总分）**：

- 岗位业务核心度 ≤ 2 分
- 试用期不缴社保
- 要求签租金贷/培训贷
- 合同主体与面试公司不一致

### 9.3 谈薪

| 能谈 | 不能谈 |
|---|---|
| 无责底薪占比 | 超出岗位带宽的数字 |
| 入职时间 | 没有对标依据的要求 |
| 岗位级别（有实习可争取） | 编造其他 offer 施压 |
| 试用期时长（不违法定上限） | — |

**话术框架**：表达意愿 → 给依据（同城同岗区间 + 你的匹配点）→ 提具体数字 → 给替代方案。

**只有一个 offer 时**：不编造其他 offer，可以谈但预期要低。

### 9.4 决策日志

写下：选择理由三条、放弃原因、最不确定的一项、3 个月后回看日期。没有日志，3 个月后只会记得"当时感觉还行"。

## 十、判停

**按断点判，不按总数判。** 总数只能说明"还没成"，不能说明"哪里错"。

### 10.1 先看样本够不够，再看哪一层断

**四层转化率需要样本量支撑，样本太小时只看第一层。**

| 已投份数 | 能判断到哪一层 | 不能判断什么 |
|---|---|---|
| < 10 份 | 什么都判断不了，继续投 | — |
| 10–20 份 | **只看「投递→被查看」** | 后面三层样本太小，波动大于信号 |
| 30 份以上 | 可以看四层 | — |

**这条是硬约束**：拿 10 份的数据去算"沟通率 20%"，等于用 2 个沟通除以 10，一个偶然事件就会让结论翻倍。

| 断点（哪层低于下限） | 说明什么 | 通常有效（不是必须） |
|---|---|---|
| 短期内大量投递，**四层全部低于下限** | 方向错了，不是措辞问题 | 回方向重做，别改简历 |
| 只看投递→查看 低于 30% | 简历入口有问题：期望岗位名称、期望薪资、到岗时间、头像 | 先改这四项 |
| 查看→沟通 低于 20% | 简历内容没对齐 JD | 对齐 JD 关键词、补成果量化 |
| 沟通→邀约 低于 20% | 投的方向或公司层次错配 | 换投递口径，不是再加投 |
| 邀约→offer 低于 15% | 面试环节 | 进面试那节，不要再动简历 |
| 投 30 份 0 查看，且已用当地可到岗表述 | 地域在筛你 | 换城，或先落脚再投 |
| 沟通 ≥ 5、面试 0 | 到岗时间或薪资预期挡住了 | 先问这两项，不是简历问题 |
| 面试 ≥ 3、offer 0 | 面试表达 | 进面试那节 |
| 只有 1 个 offer | 没有对比对象 | 不用做加权表，直接进落地 |
| 谈薪 2 轮无变化 | 对方没有再让的空间 | 继续谈的收益接近零；接不接受由他定 |

**"回 M3"不是重走一遍 M3**，是回到 M3 第二节（宽口径清单法），用投递数据重新看两件事：专业口径判断对不对、岗位名够不够具体。**不要回去从"三个问题"重新问起。**
