# M3 · 方向与岗位

> 解决什么：投什么岗位；本专业就业面窄怎么办。
> 不解决"简历怎么写"（M4），不解决"去哪个城市"（M5）。

---

## 一、先判断：本专业就业面是宽还是窄

| 信号 | 怎么查 | 命中说明 |
|---|---|---|
| 对口岗位数量少 | 平台搜「专业名 + 招聘」，同城结果 < 10 条 | 窄 |
| 学历门槛高于本科 | 对口岗位普遍要求硕士及以上 | 窄 |
| 需要执业资格 | 教资、护士执业、法律职业资格、注册会计师等，短期难拿 | 窄 |
| 地域高度集中 | 岗位只在少数城市 | 窄 |

**命中 2 条以上 = 窄口径**，走第三节。命中 0–1 条 = 宽口径，走第二节。

---

## 二、宽口径：对口岗位清单法

1. 列出专业对应的 3–5 个岗位名（要具体，不是"教育行业"）
2. 每个岗位抓 5 条 JD
3. 统计高频要求，出现 ≥ 10 次的是硬门槛
4. 对照 M0 的资产，列出"有 / 没有"
5. 输出：1 个主投岗位 + 2 个备选 + 差距清单

**岗位名必须具体到能搜出 10 条以上真实 JD。** "运营类""数据方向""互联网"都不合格。

### 2.1 学历卡点：同一个岗位名，不同企业卡得不一样

**"我这个学历能投什么"这个问题问错了。** 正确的问法是"**这类企业**卡不卡我"——因为同样叫"Java 开发"，外包公司不卡，金融科技卡到死。

下表以软件/IT 行业为例，其他行业结构类似，换成对应企业类型即可：

| 企业类型 | 校招卡不卡院校 | 卡在哪一关 | JD 里的信号 |
|---|---|---|---|
| 互联网大厂 | 隐性卡 | 简历筛选（院校库过滤） | 不写学历，官网投递系统按学校分桶 |
| 外企 / 合资 | 半卡 | 简历筛选 | 写"本科及以上"，实际偏好 211 / 重点 |
| 金融科技（银行科技子、券商 IT） | **卡最严** | 简历筛选 + 笔试 | 写"985/211 优先"或"重点院校" |
| 国企 / 央企信息中心 | 卡 | 简历筛选 + 笔试 | 写"本科及以上"，按名录筛；常加党员 / 硕士要求 |
| 军工院所 | 卡到死 | 每一关 + 政审 | 写"硕士优先""本科限 985" |
| **外包**（软通、中软、法本、中电金信类） | **完全不卡** | 缺人就面 | 写"大专以上""学历不限" |
| **中小软件公司 / 行业软件** | **基本不卡** | 看作品与面试 | 写"大专以上"或不写 |
| 传统行业 IT 部门 | 大国企卡，私企不卡 | 简历筛选 | 写"本科及以上"，实际宽松 |

**JD 信号速查（最实用的部分）**：

| JD 怎么写 | 真实含义 |
|---|---|
| "985/211 优先" / "重点院校" | **真卡**。双非简历大概率过不了筛 |
| "本科及以上" | 卡本科不卡学校层次。专科不行，双非本科可投 |
| "硕士优先" | 本科能投，但硕士优先。双非本科要靠实习和项目补 |
| "学历不限" / "大专以上" | 完全不卡。大概率外包或急招的小公司 |
| 不写学历要求 | 小公司 / 外包，不卡 |

`[通用·2026·需按实际投递验证]`

**规律只能用于初筛，不能替代实测**：同一家公司的不同业务线差异很大。兜底方法是同类型公司投 10 份，看回复率。

**这一节和 M5 的关系**：城市的「岗位适配度」维度直接引用本表——某城的岗位多，但都是卡院校的类型，适配度就是低分。

### 2.2 沟通密度：用 JD 关键词判断，不要让用户自评性格

很多人说"我不想跟人打交道"，这句话没有可操作性。**能操作的是：看 JD 里出现哪些词。**

| 沟通密度 | JD 里的词 | 典型岗位 |
|---|---|---|
| **高：对外情绪劳动** | 对接客户、维护客户关系、处理投诉、商务谈判、客户成功、对外沟通、驻场、支持一线 | 销售、客户成功、实施、售前 |
| **中：技术性沟通** | 需求评审、接口联调、code review、跨部门协作、技术方案评审、周会汇报 | 几乎全部研发岗 |
| **低：对内为主** | 独立完成、后台开发、算法、运维、数据仓库 | 后端、算法、运维、数仓 |

**要单独标注的一类：表面是技术岗，实质是客户对接。** 名字里带"技术"，日常是接客户电话、上门部署、处理投诉。

| 岗位名 | 为什么容易误判 |
|---|---|
| 技术支持工程师 | 一线处理客户问题 |
| 实施工程师 | 驻场客户现场 |
| 售前技术支持 | 陪销售见客户做方案 |
| 客户成功经理 | 服务客户续约 |
| 解决方案顾问 | 本质是售前 |
| 数据分析师 | 要给业务方反复汇报，业务方就是"内部客户" |
| 测试工程师 | 要和开发争 bug 归属、和产品对需求 |

**必须校准的三件事**（否则等于给出不现实的承诺）：

1. **完全无沟通的岗位不存在。** 纯后端也要写文档、参加站会、做 code review。低沟通 ≠ 零沟通，多数岗位仍有 20–30% 的时间在沟通。
2. **能选的是"对内"还是"对外"**，不是"有没有"。排斥情绪劳动的人，应该排除"对外"，不必排除全部沟通。
3. **低沟通有代价**：晋升往往依赖跨部门协作与向上汇报。这个代价必须说出来，让用户自己权衡"少说话"与"晋升快"。

## 三、窄口径：三条路

> 适用于"本专业能投的岗位少、或不想从事本专业"的人。三条路都不需要先有工作经验。

| 路径 | 适合谁 | 做法 | 代价 |
|---|---|---|---|
| **A 对口降门槛** | 还想留在本行业 | 中小企业、非核心岗、外包、新业务线 | 起薪低、成长慢 |
| **B 技能迁移** | 有一项可展示技能 | 用可迁移能力进相邻岗位（见下表） | 需要作品集或补一个缺口 |
| **C 低门槛高上限** | 暂时没有技能 | 销售、运营、教培、客服、门店管理 | 前期辛苦、淘汰率高 |

**优先顺序**：B > A > C。原因：B 能保住已有积累，C 是从零开始但天花板不低，A 最容易陷入低水平循环。

**判断依据**：不看"我喜欢什么"，看"我手上有什么能换成钱"。

## 五、任意专业的生成方法（五步）

当用户专业不在上表，按这五步现场生成，**输出必须是同样五列**。

### Step 1 拆对口岗位池

```
平台搜「专业名 + 招聘」，记录：
- 同城岗位数
- 学历要求分布
- 是否要求执业资格
- 岗位集中在哪些城市
```

### Step 2 判断窄在哪

| 判断 | 结论 |
|---|---|
| 岗位 < 10 条 | 数量窄 |
| 多数要求硕士 | 学历窄 |
| 必须持证 | 资格窄 |
| 只在 1–2 个城市 | 地域窄 |

**命中 2 条以上 = 窄口径。**

### Step 3 盘可迁移能力（只用动词）

从四类材料里提取：课程、实训/项目、实习、日常爱好。

| ❌ 名词 | ✅ 动词 |
|---|---|
| 沟通能力 | 协调、说服、安抚、访谈、宣讲 |
| 数据分析 | 清洗、建模、可视化、归因、复盘 |
| 写作能力 | 检索、结构化、改写、校对、叙事 |

每条能力必须能举出一个具体例子，否则删掉。

### Step 4 匹配相邻岗位（三种邻近）

| 邻近类型 | 含义 | 例子 |
|---|---|---|
| **能力邻近** | 用同样的能力，换一个岗位 | 学前教育 → 教培教研（同样要懂课程与儿童） |
| **行业邻近** | 留在同行业，换一个职能 | 护理 → 医药销售（同样懂临床场景） |
| **场景邻近** | 换行业，但工作场景相似 | 酒店管理 → 客户成功（同样处理客户问题） |

**每类至少给 1 个，总共给 3–5 个候选。**

### Step 5 算最短缺口

| 缺口类型 | 补齐周期 | 判断 |
|---|---|---|
| 作品集 | 数周（差异大） | 优先，最快能补 |
| 证书 | 3–12 个月 | 次选，看是否硬门槛 |
| 行业知识 | 数周 | 可通过 JD + 行业报告速成 |
| 销售能力 | 无法速成 | 只能通过实习验证 |

**只选一个**，选短期内能补完的。选三个等于没选。

## 六、输出（五列必须填满）

```
【判断】主投岗位：__；备选：__、__
【专业口径】宽 / 窄；窄在哪：__
【依据】
  [检索·yyyy-mm·平台] 「__」同城岗位 __ 条，学历要求 __
  [自填·日期] 可迁移能力：__、__、__
【动作】在 __ 前，补齐 __（一个缺口），完成的标志是 __
【会推翻这个判断的情况】
  ① 目标岗位实际 JD 数量 < 10
  ② 补齐缺口后投 20 份仍 0 沟通
```

**输出完这一段，下一步不是改简历，是去找 JD。**

| 顺序 | 做什么 |
|---|---|
| 1 | 按上面的岗位建议，检索 3–5 条真实 JD |
| 2 | 从 JD 里提出高频词（工具、方法、业务场景） |
| 3 | 再动简历，把经历往这些词上靠 |

**跳过第 1 步直接改简历，改出来的是一份"通用版"**——看起来完整，但每个岗位都不匹配。详见简历模块的「没有岗位 JD 时的顺序」。

## 七、判停

| 条件 | 动作 |
|---|---|
| 岗位名超过 3 个 | 收敛到 1 主 2 备 |
| 三问交集为空 | 降一项要求（城市/加班/起薪/稳定性） |
| 改了三轮还在改方向 | 不是判断不够，是信息不够。给"投 10 份测一次"这个选项，**由用户决定**，不替他喊停 |
| 用户说"我再想想" | 给 48 小时期限，到期无论想没想清都投 5 份 |
| 用户坚持"必须对口" | 给对口岗位的真实数量与薪资，让他自己判断 |
| 用户想转的行业完全无经验 | 先做能力邻近，不要一步跨到行业邻近 |
| 用户说"不想跟人打交道" | 不按岗位名判断，用 2.2 的 JD 关键词筛；同时校准"完全无沟通的岗位不存在" |
| 用户因"太卷"要换方向 | 先问投过没有。没投过，"卷"是预判不是实测；投过，按 `06-apply.md` 四层转化率看断在哪一层 |
| 用户只报学历、要求推荐岗位 | 不给岗位名单，先按 2.1 判断"哪些类型企业卡他"，再定岗位 |

**反模式识别**：当用户问"是不是还缺一套更完整的求职方法"时，先答一句**"不缺"**。补方法论有产出感、不改结果，是最舒服的逃避。
