# M4 · 简历

> 解决什么：没简历怎么从零建；有简历怎么改。
> 核心原则：**简历不是作品，是筛选器。它唯一的任务是让你进入下一轮。**

---

## 〇、动笔前：两件事必须先做完

**简历不是写出来的，是把已经挖出来的东西排上去。** 如果下面两项没完成，先回去做，不要直接动笔——否则写出来的全是形容词。

| 必须先有 | 在哪做 | 完成的标志 |
|---|---|---|
| **经历深挖** | 资产盘点里的深挖环节 | 每段经历至少 3 个动作 + 1 个可查交付物 |
| **目标岗位的 3–5 条真实 JD** | 见下一节 | 提得出高频词 |

**技能不需要前置。** 用户报的工具默认按"能独立完成工作"处理，直接写进技能栏——但要在输出里说明这个默认，给他纠偏的机会。

---

## 〇.1 没有岗位 JD 时的顺序

**不能跳过 JD 直接改简历。** 简历是筛选器，筛选器必须对着筛子调。

```
没有目标岗位
  → 按技能与经历给 2–3 个岗位建议（每条带匹配理由）
  → 检索这些岗位的真实 JD，每个岗位取 3–5 条
  → 从 JD 里提高频词（工具、方法、业务场景）
  → 再动简历：把经历往这些词上靠
```

**为什么必须检索真实 JD**：凭印象会漏关键要求。例如"新媒体运营"，你想的是剪视频、写文案，实际 JD 里常有"投流、GMV、直播间转化"——这些词决定简历该突出什么。

**检索量**：每个岗位 3–5 条。少于 3 条看不出共性，多于 5 条边际收益很低。

**如果用户不愿意检索**：让他凭印象说 3 条记得的要求，标注"未核实"，然后改——但输出里要写明这可能偏差。

**检索方法**见岗位检索模块；不想用脚本，就用搜索引擎的 `site:` 聚合。

| 状态 | 走哪条 |

## 二、从零构建：七块结构

### 2.1 标准结构（应届生一页）

```
姓名
求职意向：__（一个具体岗位）｜可到岗时间：__
电话｜邮箱｜现居城市（可选）

教育背景
学校 · 专业 · 学历 · 起止时间
主修课程：只写与岗位相关的 4–6 门

实习经历（无则删掉此栏）
公司 · 岗位 · 起止
• 做了什么（动词开头）
• 结果是什么（能算出来的数字，或可验证的产出）

项目经历
项目名 · 角色 · 起止
• 解决什么问题
• 用了什么方法/工具
• 结果是什么

校园经历（无实习时的主要素材）
组织 · 角色 · 起止
• 你负责的部分
• 结果

技能与证书
工具：__（到什么程度）
证书：__（只写已获得）
```

### 2.2 每块"没东西可写"怎么办

| 块 | 零经历写法 |
|---|---|
| 实习 | 没有就删掉，不要编。用项目与校园经历补 |
| 项目 | 课程大作业、实训、自学作品都算。写清"问题—方法—结果" |
| 校园 | 社团、班委、志愿、比赛组织，只写你负责的部分 |
| 技能 | 写工具不写形容词："Excel 透视表与 XLOOKUP" 而不是 "熟练办公软件" |

### 2.3 三条硬规则

1. **一页**。应届生超过一页，说明不会取舍
2. **一个岗位一份**。求职意向只写一个岗位名
3. **PDF + 规范文件名**：`姓名-岗位-城市-届别.pdf`

## 三、有简历：五维诊断

每维给"合格 / 需改 / 不合格"，并说明改哪一句。

### 维度 1：结构

| 检查 | 不合格表现 |
|---|---|
| 有没有求职意向 | 没写，或写了两个岗位 |
| 顺序是否合理 | 教育背景占了半页，实习只有两行 |
| 有没有无关信息 | 身高体重、家庭成员、身份证号 |

### 维度 2：匹配

| 检查 | 不合格表现 |
|---|---|
| 是否对着 JD 改 | 一份简历投所有岗位 |
| 关键词是否对上 | JD 要"数据分析"，简历写"数据整理" |
| 经历排序 | 与岗位最相关的放在最前 |

### 维度 3：可信度（最重要）

**三层追问测试**：每个数字问三句，答不出就改。

| 层 | 问题 | 答不出说明 |
|---|---|---|
| 1 | 这个数字怎么算的？ | 数字是编的 |
| 2 | 基准是什么？和谁比？ | 没有对照组 |
| 3 | 你个人贡献占多少？ | 把团队成果写成个人成果 |

**高风险表述 → 改法**

| ❌ 高风险 | 为什么 | ✅ 改为 |
|---|---|---|
| 效率提升 99% | 等于耗时降 100 倍，不合常识 | 建立标准化清洗流程（去重、异常值剔除、口径统一），并将清洗环节脚本化 |
| 成本压缩 60% | 实习生让部门降 60%，说不清基准 | 将复盘所需字段预先加工为固定口径报表，复盘时直接调用 |
| 降低 8% 运营费用 | 实习生主导降 8% = 总监级表述 | 删除 |
| 提升点击率 1%，转化率 +0.5% | 两者比例不符常识 | 通过标题与主图 A/B 测试优化核心 SKU 点击表现 |
| 月销环比增长 10% | "协助"撑不起 10% 归因 | 配合主管调整促销节奏与定价，期间单品销量环比提升（去掉归因） |
| 精通 SQL/Python/Excel | 过度声称 | 熟练使用 SQL、Excel；掌握 Python 基础分析 |

**原则**：过程描述同样有说服力，而且经得起追问。

### 维度 3.1 改前改后对照（真实案例，运营岗）

**这一段解决"知道要改，但不知道改成什么样"。** 下面五组都来自实际简历，左边是原句，右边是能扛住追问的写法。

| # | 改前（原句） | 问题 | 改后 | 为什么 |
|---|---|---|---|---|
| 1 | 用漏斗模型拆解访客路径，优化 SKU 标题与主图，**推动 CTR 提升 15%、转化率提升 8%** | 点击率涨 15%、转化率只涨 8%，比例反常识；实习生归因太强 | 用漏斗模型拆解访客路径，**定位到搜索页流失最高**；对 3 个核心 SKU 做标题关键词与主图 A/B 测试，两周内选定版本 | 写"定位到什么"和"做了什么测试"，结果交给面试官判断 |
| 2 | SQL 透视分析品类转化路径，**月报制作时间成本压缩 60%** | 基准是谁的时间？说不清 | SQL 透视分析品类转化路径，**定位到 2 个高漏损环节**；将复盘所需字段预先加工为固定口径报表，之后每月直接调用 | 把"压缩 60%"换成"预先加工、直接调用"——同样说明提效，但可核查 |
| 3 | 发现推广资源配置偏差，**助力促销季整体费用降低 8%** | 实习生主导降 8%，是总监级表述 | 通过 CAC/ROI 对比发现两个渠道的配置偏差，**输出一页调整建议**；方案由主管决策 | 只写"发现了什么、输出了什么"，不写"产生了什么结果" |
| 4 | **协助主管实现**相关类目单品月销量环比增长 | "协助"撑不起增长的归因，且无数字 | 对标头部竞品输出策略周报，**配合主管调整促销节奏与定价**；期间单品销量环比增长（团队口径，未拆分个人贡献） | 把归因改成"配合"，并主动标注口径——这比硬撑可信 |
| 5 | 大促高并发期间**保证库存准确率** | "保证"是形容词，不是事实 | **制定商品上下架 SOP**，大促期间每日核对库存与在架状态，异常项当日同步客服 | 用"做了什么动作"替代"保证了什么结果" |

**三条改写规则**（比背模板有用）：

```
① 数字要么能扛三层追问（怎么算的 / 和谁比 / 你占多少），要么去掉，只留动作
② 团队成果不能写成个人成果，说清你负责哪一环
③ "保证""实现""助力""推动"这类词，**后面没有具体动作就换掉**——不是不能用，是不能单独用
```

**为什么"过程描述"不吃亏**：面试官关心的不是"你 headline 多漂亮"，而是"你是不是真做过"。写得细，反而证明你在场；写得大，第一轮追问就露。

### 维度 3.2 用 STAR 重写一段经历的步骤

**STAR 不是四个词，是四道筛。** 大多数人的问题不是不会写，是四格填不满：

| 格 | 要问自己 | 填不满怎么办 |
|---|---|---|
| **S 情境** | 当时的背景是什么？为什么这件事需要做？ | 一句话交代即可，不要写公司介绍 |
| **T 任务** | **你**负责哪一块？（不是团队负责什么） | 如果只是配合，就写"配合 XX 完成 XX 环节" |
| **A 动作** | 你具体做了哪几步？用了什么方法/工具？ | **这一格必须最详细**，3–5 个动作 |
| **R 结果** | 结果是什么？有数字写数字，没数字写变化 | 答不出数字就写"交付了什么"，不要编 |

**操作顺序**：先把 A 写满 3–5 条，再回头补 S/T，最后看 R 能不能配上。**先写结果的人，往往在编。**

**如果有人要求你写出没测过的数字**，三步连着给，缺一步他就会自己编：

1. **拒绝，但给理由**——不是"不道德"，是"这句话会在面试第二问崩掉"。
2. **给替代写法**——动作 + 交付物："负责 XX 环节执行，每周产出 N 篇"。写他确实做过的部分。
3. **给一句成本说明**，用来对付"大家都这么写"：HR 一天看两百份，编的数字长得都一样，真数字反而显眼。

**一个填满的示例**（运营岗，可套用）：

```
S：大促期间店铺流量上涨但转化下滑，需要定位流失环节
T：我负责访客路径的数据拆解与 SKU 页面的优化测试
A：① 用漏斗模型拆解"曝光→点击→详情→加购→支付"五段，算出各段流失率
   ② 定位到搜索页流失最高（比行业均值低 12 个百分点）
   ③ 选 3 个核心 SKU，改标题关键词 + 换主图，做两周 A/B 测试
   ④ 每周出一次对比表，同步给主管决定是否全量
R：两周后搜索页点击表现优于原版本，选定版本全量替换；具体提升幅度由平台数据口径决定，我这里记录的是测试结论
```

### 维度 4：格式

| 检查 | 要求 |
|---|---|
| 页数 | 1 页 |
| 格式 | PDF |
| 文件名 | `姓名-岗位-城市-届别.pdf` |
| 字体字号 | 正文 10–11pt，标题加粗，不超过 2 种字体 |
| 留白 | 页边距足够，不挤成一团 |

### 维度 5：篇幅与密度

| 问题 | 改法 |
|---|---|
| 自我评价占 5 行 | 删掉，或压成 1 行能力概述 |
| 每段经历 6 条 bullet | 压到 2–3 条，只留最相关的 |
| 课程列了 12 门 | 只留与岗位相关的 4–6 门 |

## 四、作品集（部分岗位必需）

| 岗位 | 是否必需 | 最小规格 |
|---|---|---|
| 剪辑 / 视频 | 必需 | 3–5 条成片 + 每条 30 字思路 |
| 设计 / 美工 | 必需 | 6–10 张成稿，同主题至少 3 张 |
| 内容 / 新媒体 | 强烈建议 | 3–5 篇代表作，或 1 个账号的数据截图 |
| 运营 / 数据 | 加分 | 1 份完整分析报告（脱敏） |
| 其他 | 可选 | — |

**形式**：PDF（10 页内）或在线链接。链接要能直接打开，不要放网盘。

## 五、输出：优先给三条改进，不强制出文件

```
【判断】这份简历现在能用 / 需要改 __ / 不建议投
【最该改的三条】（按影响排序）
  ① 第 __ 行的「__」→ 改为「__」
  ② __
  ③ __
【可信度】有 __ 个数字答不出追问，建议改为过程描述
【下一步】在 __ 前改完这三条，完成的标志是能对着简历讲 10 分钟不卡
```

**是否生成文件**：用户明确要才生成。默认只给建议——改简历的价值在判断，不在排版。

## 六、边界：本模块只做诊断，不做投递决策

**M4 不规定"改几轮才投"。** 简历改到什么程度、什么时候投，由用户自己决定——那是他的判断，不是工具的判断。

M4 只负责一件事：**根据简历与目标 JD，给出具体的修改建议。**

| 本模块负责 | 不负责（归 M6） |
|---|---|
| 指出哪句话经不起追问 | 投多少份 |
| 给出改前改后的具体写法 | 什么时候开始投 |
| 判断简历与 JD 的匹配缺口 | 投了没回音怎么办 |

**为什么把投递判断全部移到 M6**：三个模块都规定"改几轮就投"，会互相锁死——M3 说改三轮投、M4 说改两轮投、M6 说投 10 份回 M3，用户会在三个"停"之间来回跳，永远出不去。

**唯一要回答的一句**：用户明确问"我该继续改还是该投了"时，答"改简历的边际收益在两轮之后急剧下降，建议投 10–20 份拿真实反馈，再回来改"。**但决定权交给用户，不替他设死线。**

**本模块内部的判停只有一条**：数字答不出三层追问 → 改成过程描述，不保留。
