# M0 · 个人档案

> 解决什么：在没有事实基础的情况下给建议，等于算命。这个模块只做一件事——把"我是谁、我有什么、我缺什么"变成可核查的清单。

---

## 一、四个判定（先问，不猜）

| # | 问题 | 用途 |
|---|---|---|
| 1 | 你现在几年级？（大一/大二/大三/大四/已毕业） | 决定阶段地图 |
| 2 | 你的学校层次？（双一流 / 普通本科 / 独立学院与民办本科 / 专科 / 专升本） | 决定可触碰的岗位门槛与竞争位置 |
| 3 | 你有简历吗？（有定版 / 有草稿 / 没有） | 决定 M4 走诊断还是从零建 |
| 4 | 你有明确想投的岗位和城市吗？（都有/只有岗位/只有城市/都没有） | 决定是否可直接进 M6 |

**关于学校层次**：它决定"哪些岗位在筛选阶段就会被卡"，是**概率判断**，不是能力评价。不要用"你学校一般所以别投"这种表述，要给"这类岗位历年卡不卡学校"的具体依据。

**答不出时**：给二选一或区间，不追问第三次。

---

## 二、六类资产盘点

**提问方式（重要）**：先让用户**自由说**，不要给模板。

"每件写清：我做了什么 + 结果是什么"这种句式，对多数人无效——他们要么卡在"结果是什么"，要么把没结果的事直接跳过。正确顺序是：

1. 让用户想到什么说什么，越具体越好；
2. 助手听完后，按「情境 — 动作 — 结果」帮他提炼；
3. 只追问缺的那一格，不要求他重新组织语言。

逐类问，每类只记"有证据的"，不记"感觉有的"。

### 2.1 技能

| 类型 | 要问到的粒度 | 例子 |
|---|---|---|
| 课程技能 | 学过哪些与岗位相关的课，做过什么作业 | 统计学、数据库、Excel 数据分析 |
| 工具技能 | 会用哪些软件，到什么程度 | Excel 透视表、SQL 查询、PR 剪辑、PS 抠图 |
| 自学技能 | 自学过什么，有没有产出 | 跟着课程做过一个数据分析项目 |
| 语言与其他 | 英语等级、方言、驾照 | CET-4/6、普通话二甲 |

**判断标准**：能当场做出一个东西，才算"会"；只听过课，算"了解"。

**问法要求（重要）**：不要给一份固定清单让人对号入座。不同专业的工具差异很大，列全必然漏。

正确问法是**举例 + 开放式收尾**：

> "你用过哪些工具或软件？比如 Excel、剪辑、PS 这类，也包括课程里学过的、实习里用过的系统，或者自己摸索过的。"

**先让用户自由说，助手再归类。** 不要要求他按"课程/工具/自学"分类回答——大部分人说不出自己属于哪一类，但说得出"我用过什么"。

### 2.2 校园经历

| 类型 | 要问 | 算数的条件 |
|---|---|---|
| 社团/学生会 | 担任什么角色，组织过什么 | 你负责的部分有结果 |
| 班委 | 具体做了什么 | 有可描述的动作 |
| 志愿活动 | 时长、角色 | 有组织方证明 |

### 2.3 实习

| 要问 | 记录 |

| 做过的 3 件具体事 | |
| 1 个可量化结果 | 有则记，没有写"无可量化结果" |

### 2.4 竞赛

| 要问 | 记录 |
|---|---|
| 名称、级别、时间 | |

**范围**：公司项目、课程大作业、实训项目、竞赛作品、自己做的作品都算，不要求是真实商业项目。

| 要问 | 记录 |

### 2.7 深挖：把"会"变成"能证明"

用户说"我会剪映""我做过小红书"，这两句写进简历一文不值——**没法验证**。这一步的任务是把它们变成可写、可追问、可证明的东西。

**资产盘点只完成了一半。用户报完清单，必须往下一层挖，否则后面写简历只能堆形容词。**

#### 技能定级：四级，只用一个问题

| 级 | 标准 | 能拿出什么 |
|---|---|---|
| 了解 | 上过课、看过教程，没独立做过 | 无 |
| 会用 | 照着教程能做，离开教程就卡 | 练习稿 |
| 独立完成 | 给需求能自己做出来，不用问人 | 作品 |
| 能解决问题 | 遇到没见过的也能搞定，能讲清为什么这么做 | 作品 + 取舍说明 |

**定级只问一句**：「上次做这个东西，你花了多久，中间卡在哪？」

- 答不出卡在哪 → 停在「了解」
- 说得出卡点和怎么绕过去的 → 「独立完成」以上
- 能说出「为什么选这个方案不用那个」→ 「能解决问题」

**不要问"你熟练吗"。** 所有人都说自己熟练，这个答案没有信息量。

#### 经历深挖：每个经历问四句

| # | 问什么 | 答不好说明什么 |
|---|---|---|
| 1 | 这件事几个人做的？你负责哪一块？ | 答不清分工 = 大概率是旁观者 |
| 2 | 具体做了哪几步？（要 3 步以上） | 说不满 3 步 = 没真做过 |
| 3 | 结果是什么？有没有留下能看的东西？ | 拿不出文件、数据、截图 = 无法写进简历 |
| 4 | 如果重做一次，你会改哪里？ | 答"会做得更好" = 没思考过 |

**第 4 问最关键。** 真做过的人一定知道哪里做得不好，因为他在过程中吃过亏。没做过的人只能给形容词。

#### 挖不出数字时的三种替代

| 情况 | 怎么写 |
|---|---|
| 有数据但不敢写 | 写动作和口径，不写结论（见简历模块的改写规则） |
| 完全没有数据 | 写清"做了什么 + 交付了什么"，用名词不用形容词 |
| 连交付物都没有 | **这段不要写**，写上去反而减分 |

#### 判停

| 条件 | 动作 |
|---|---|
| 技能四项以上停在「了解」 | 先选 1 项推到「独立完成」，再谈简历 |
| 所有经历都答不满 3 步 | 不是简历问题，是确实没做过。先去做一件能做完的小事 |
| 经历里有对外材料（公众号、通知、话术） | 优先挖这条，它比"会用工具"硬 |

## 三、约束条件

| 项 | 为什么要问 | 影响哪个模块 |
|---|---|---|
| 意向岗位（可空） | 决定方向 | M3、M4、M6 |
| 意向城市（可空） | 决定城市池 | M5、M8 |
| 可接受的最低月薪 | 决定岗位筛选线 | M3、M6 |
| 家庭能否支持 | 决定能承受多久空窗 | M6、M10 |
| 可动用资金 | 决定能否异地实习/求职 | M8、M10 |

**不采集"每天/每周能投入多少小时"。**

两个原因：

1. **问出来的数字不可信。** 在校生的时间是碎片的——课表、考试周、社团、突发事，每周承诺 10 小时的人，实际能连续投入的可能只有周末两段。按一个假数字排出来的计划，第一周就会崩。
2. **排时间表不是这个 skill 的职责。** 它给的是"最短路径 + 完成标志"，不是日程表。用户每天有多少时间，他自己比我们清楚。

对应做法：**只给建议与完成标准，不做时间分配。** 比如"这项技能的最小产出是 3 条成片"，而不是"每周 6 小时，第 4 周完成第 2 条"。前者用户能自己塞进任何空隙，后者一崩就全废。

## 四、输出：一份档案 + 一个入口

```
【判断】你现在的阶段：__；最该先做：__
【资产】技能 __ 项｜校园经历 __ 段｜实习 __ 段｜竞赛 __ 项｜项目 __ 个｜证书 __ 个
【缺口】距离目标岗位，最缺的是：__
【动作】在 __ 前，补齐 __，完成的标志是 __
【假设】若某些信息缺失，本轮按 __ 推演
```

**档案落到** `assets/profile.md`，后续模块只读这份，不重复问。

## 五、判停

| 条件 | 动作 |
|---|---|
| 用户说不清自己会什么 | 改用"做过什么"提问，从具体事倒推技能 |
| 用户没有任何实习/项目/竞赛 | 不诊断，直接进 M2 或 M4 的"零经历写法" |
| 用户不愿提供成绩/家庭情况 | 跳过，标 `[未提供]`，不影响主流程 |
| 盘点超过 30 分钟 | 停止，先给当前能给的结论，剩余边做边补 |
