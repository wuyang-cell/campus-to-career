# 活跃优先与去重规则

## 活跃优先（active-first）

### 1. 硬过滤（直接剔除）

标题、公司名或状态字段命中以下任一关键词的条目剔除：

```
停止招聘 / 已暂停 / 已下线 / 暂停招聘 / 停止职位 / 已结束
```

### 2. 新鲜度信号（采集时尽量获取）

| 信号 | 来源 | 说明 |
|---|---|---|
| `sortFlag=15` | 猎聘 URL 参数 | 按最新发布排序，抓取时默认启用 |
| search recency = week | 搜索引擎聚合 | 只取近 7 天索引的结果，最多放宽到 month |
| 活跃时间 | BOSS 字段 | "刚刚活跃/今日活跃/3日内活跃" 优先 |
| 发布时间 | 各平台列表字段 | 2 周内为高活跃；>1 个月降权并标注 |

### 3. 排序规则（默认，可被用户偏好覆盖）

```
活跃/发布时间新鲜（周内 > 月内 > 更早）
  → 多平台在招（同一岗位在 ≥2 个平台出现，加权；说明真实在招且急招）
    → 薪资明确（有具体区间 > 面议）
      → 与用户画像匹配度
```

- 薪资"面议"不剔除，排序靠后并标注 `面议`
- 无法判断活跃时间的条目标注 `活跃度未知`，排在有明确时间之后

## 跨平台去重（dedup）

### 主键

```
dedup_key = norm(公司名) + "|" + norm(岗位名) + "|" + norm(城市)
```

规范化函数 `norm()`：
- 去首尾空格、全角空格 → 半角
- 去中英文方括号/圆括号内的城市、区域、数字（如【急聘】、(北京)、(3)）
- 统一大小写（英文岗位名）
- 公司名去"有限公司/有限责任公司/股份有限公司"等后缀再比对

### 合并规则

| 情况 | 处理 |
|---|---|
| 同公司+同岗位名+同城市 | **合并为一条**：sources 追加平台与链接；薪资取更新鲜一方的值；JD 取更完整一方；活跃度取最新 |
| 同公司+不同岗位名 | 保留为独立条目 |
| 不同公司+同岗位名 | 保留为独立条目 |
| 标题仅差级别词（初级/高级/资深/Junior/Senior） | **不合并**，视为不同岗位 |
| 猎头发布（公司显示"某公司/猎头"） | 与直招条目并存，标注"猎头直推" |

### 实现脚本

```bash
# 纯标准库，无第三方依赖
python3 scripts/dedup_merge.py --input merged.json --out final.json --format md
```

`merged.json` 为各平台采集结果拼接的数组（元素含 title/company/salary/location/job_desc/activity/sources 字段）。脚本输出去重后的 JSON 与 Markdown 清单，并打印合并统计（去重前/后条数、合并对数）。
